## 未完了・既知の問題

1. **GUI起動時インストール失敗**：隔離GUIの起動スクリプトが
   `Package was expected to be installed but not found: panda_toon` を報告。
   続く `addon_utils.check(module_name) == (True, True)` のassertionで停止し、
   Blenderは終了コード1。手動GUIチェックとスクリーンショット取得には未着手。
   原因は未確定。バックグラウンドで成功したインストール経路とGUI経路を、まず
   同梱ソースの読み取りで比較すること。製品不具合や非同期問題と断定しないこと。
2. **保存プレビュー**：Windows版Blender内部がプロファイルの`.thumbnails`へ
   書き込みを試みた。専用プロセスで `file_preview_type = 'NONE'` を設定した
   保存・再読込は成功し、その保存経路では再発なし。通常設定には保存しない。
   この設定は全ファイルアクセスを制限するものではない。
3. **同梱ブラシ警告**：C:の同梱ブラシ参照をD:のシーン保存先に相対化できない
   Blender本体の警告。製品ZIPにブラシは含まず、確認済みのインストール・読込・
   保存に支障なし。別PCへの検証シーンの可搬性は未保証。
4. **標準テスト手順の未統合**：`tools/run_blender_tests.ps1` と
   `tests/blender/phase1a.py` は初期版を基にしており、後続のNONE設定、オフライン
   起動、各段階の停止確認、インストール／別プロセス検証をまだ統合していない。
   現状を最新の安全な実行手順としてそのまま再実行しないこと。
5. 過去資料には当時の未検証表記、ローカル絶対パス、今回除外したLabへの参照がある。
   会社PCでそれらのパスは使用しないこと。最新状況はこの文書を参照。
6. Cycles、透明度、独立したライトカラー制御、設定アニメーションは対象外／未対応。
   生成ボタンは既存面の割当を自動置換せず、新規スロットを追加する仕様。

## 会社で最初に行うこと

1. このWIPブランチを取得し、Git状態、Blender実バージョン、実行ファイルパス、
   現地の安全条件を確認する。通常設定や業務ファイルを検証に使わない。
2. Blenderを起動しない検証を実行する：

   ```powershell
   python -B tools/check_static.py
   python -B -m unittest discover -s tests/unit -v
   ```

   標準ライブラリの`tomllib`を使うため、通常Pythonは3.11以降が必要。
   現在はPython16ファイルの構文検証と単体テスト8件。
3. GUI失敗の原因調査と検証用スクリプトの整理案を作り、差分・コマンド・入力・
   書き込み先をレビューしてから、別途承認された範囲でBlenderを実行する。
4. 新規UUID、専用設定／Extension Repository、オフライン、自動実行無効、
   NONE設定を使用する。再起動確認では専用設定を読み、factory startupを外す。
5. GUI確認はユーザーが実操作する。[手動チェック項目](phase1a-gui-closeout-preparation.md)
   を参照するが、同文書の旧ローカル起動コマンドは再利用しない。
